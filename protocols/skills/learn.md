# Structured Learning

Save a lesson only when it is project-specific, non-obvious, actionable, and
likely to recur. Generic advice already covered by instructions does not belong
in `MEMORY.md`.

Read existing entries before adding one. Delete entries whose reason no longer
holds; an expired review date alone is not enough. Rewrite surviving absolute
rules with their scope and exception, and replace superseded lessons rather
than keeping contradictory instructions.

Use one lesson per block:

```markdown
[LEARN:category]
- Rule: [what to do, where it applies, and the exception if any]
- Reason: [why the rule holds]
- Evidence: [file, command, output, or user correction]
- Date: YYYY-MM-DD
- Review by: [YYYY-MM-DD, or the event that would make the entry obsolete]
```

If a relevant session log already exists, add a brief reference to a material
lesson there rather than duplicating the entry.

Follow `Reports and Updates` in `protocols/writing.md`: state the saved lesson
and summarize any pruning or rewriting in one sentence.
